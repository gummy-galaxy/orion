# Workflows

- Keep each `run:` step to one command, ideally `lute run <script>`. Multi-line shell and multi-step logic go in a Luau script in `.lute/`, run from the repository root, so it runs locally the same way. Most belong as a subcommand of an existing category script, as [Luau style](luau-style.md) describes. Use `process.run` from `@std/process` when an argument may contain spaces. Name steps in Title Case.
- Run a script's body through `runScript` from `workspace/orion-cli/src/common/process/runScript.luau`. Lute exits 0 for some uncaught errors, such as a `process.run` whose program is missing, so without it a failed step can pass.
- Reference actions from the `actions` organization by major tag, such as `actions/checkout@v7`. Pin every other action to a commit SHA with a version comment.
- Set `timeout-minutes` to about one and a half times a measured run. Raise it only when real runs get close.
- Write every job so it can be a required check, since most are. A required check matches a job by name alone, so give each job a kebab-case ID that says what it checks and that no other workflow uses, such as `docs-deploy` rather than `deploy`, and no `name:`.
- Skip work with a job condition fed by a filter job, like `ci-loading` in `ci.yml`. Workflow-level `paths` leaves a required check waiting forever when it skips the workflow. A skipped job passes its check, so a filter job is required too: when it fails, the jobs behind it are skipped, not failed.
- The required checks live in the `Default` ruleset in the repository settings. In `ci.yml`, the `finish` job is the required check for every other job, so add a new job there to its `needs`. Elsewhere, have an admin add a new job's name to the ruleset when it should be required. A matrix job skipped by its condition reports one check under the bare job name rather than one per matrix entry, so don't require its matrix checks.
