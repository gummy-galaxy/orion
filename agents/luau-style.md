# Luau style

- Put a CLI module in the layer folder of `workspace/orion-cli/src` whose job it shares, as that package's README lays out, and require only from its own layer or below. Keep types, constants, and config tables at the top of `src`, and code that only `.lute` scripts use in `.lute/lib`.
- Put a module's tests in `<module>.spec.luau` beside it, such as `common/platform/getDataDir.spec.luau`.
- End a function's name in `Async` when it waits on a `CommandRunner`, either by calling one or by calling a function that does, such as `sources/github/api/fetchRepositoriesAsync.luau`. The suffix spreads to callers, table fields like an adapter's `collectAsync` included, so a caller can tell which calls might belong in a `task.spawn`. It stops at callbacks whose name a shared shape sets, such as a command's `run`, and skips the quick process probes `isProcessAlive` and `getParentPid`.
- Name a required module after the last part of its path, such as `local cli = require("@batteries/cli")` and `local io = require("@lute/io")`. Reach for `@std/*` first, and use a `@lute/*` library only for what `@std` lacks, such as `@lute/net/server` for the HTTP server.
- Use blank lines to show a module's structure. At the top, keep related requires, type aliases, constants, and short assignments together, and separate those groups and adjacent functions with a blank line. Within a function, separate its logical steps, such as setup, guards, loops and branches, state changes, and the final result, and keep the statements of one step together. StyLua sorts requires and formats statements but doesn't add these blank lines, so run it after editing Luau and then review the spacing yourself.
- Keep code within StyLua's 120 columns and comments within 80, counting a tab as four. Two lints flag what StyLua can't fix. `comment_width` flags a long comment, and `lute lint --auto-fix <paths>` from `workspace/orion-cli` rewraps it; move a long comment that follows code onto its own line above it. `string_width` flags a line past 120 columns that holds a string, since StyLua never splits one. Split it by hand: join pieces with `..` across lines, breaking at a sentence or a comma, or put the lines in a table and `table.concat` them. Whitespace inside a multi-line JSON fixture is free to rewrap instead.
- Keep `.lute/` to a few top-level scripts, each either a category of related jobs, such as `build`, `install`, or `report`, or a job that stands on its own, such as `mutate`. Add a new job, especially platform- or CI-only glue, as a subcommand of the category it fits, like `lute run install sqlite`. A category stays one file while its subcommands are short. Once they grow long, it becomes a folder, like `.lute/report/`, whose `init.luau` dispatches on `process.args[2]` and requires one module per subcommand with `@self/<module>`, each exporting one function and doing nothing until it's called. Don't put a file and a folder of the same name side by side, such as `report.luau` beside `report/`, since requires into the folder become ambiguous.
- `lute run analyze` checks formatting, types, and that the files `lute run generate` writes are current, which needs `npm ci` in `docs/` first. It lints with Lute's built-in rules plus Orion's own in `.lute/lints`, one folder per rule with an `init.luau` and its `init.spec.luau`, which `lute test workspace/orion-cli .lute` runs from the repository root. Add a rule there rather than reaching for another linter, and silence one spot with a `-- lute-lint-ignore(<rule>)` comment above it.
